# AI-Buddy-Avito

AI-buddy — ИИ-наставник для адаптации стажёров Авито (Hack&Change 2026). Демо на Flask и PostgreSQL использует контекст задачи, подбор инструкций с предварительной проверкой прав и имитацию сервиса заявок к Catalog Dev. Пользователь спрашивает про 403, проверяет черновик, подтверждает отправку и видит заявку после перезагрузки браузера и перезапуска приложения.

## Запуск

Нужны Docker и Docker Compose. Выполни в папке проекта.

```sh
cp .env.example .env
docker compose up -d --build
```

Если `.env` уже настроен, используй существующий файл. Открой [демо](http://127.0.0.1:5000/). Порт можно задать через `APP_PORT` в `.env`.

PostgreSQL хранит выданные права, заявки, диалог и серверные сессии в `instance/postgres`. Ключ подписи cookie хранится в `instance/web`. Эти папки исключены из Git и Docker build context. Для остановки используй `docker compose down`. Следующий запуск использует сохранённые данные.

## Пройти сценарий

1. Выбери тестовый профиль «Стажёр Каталога».
2. Напиши «На Catalog Dev вижу 403. Что делать?» или нажми готовую подсказку.
3. Посмотри ответ и раскрой источник инструкции.
4. Нажми «Подготовить заявку». «Отмена» закрывает форму.
5. Открой форму снова и нажми «Отправить заявку».
6. Проверь номер `ACC-…` и статус «Ожидает согласования».
7. Перезагрузи страницу. Диалог, номер и статус восстановятся из PostgreSQL.

Владелец стенда имитируется командой. Подставь номер своей заявки.

```sh
docker compose exec web flask --app app approve-request ACC-001
```

Нажми «Проверить статус» и спроси, как проверить исправление. Для нового прогона можно удалить тестовые заявки и историю выбранного профиля. Команда попросит подтверждение.

```sh
docker compose exec web flask --app app reset-demo --profile intern-catalog
```

Покажи второй исход той же ошибки. Выбери «Стажёр · доступ уже есть» и задай тот же вопрос про 403. Помощник подтверждает право на чтение и предлагает готовый черновик для владельца стенда с задачей и местом для деталей ошибки. Его можно скопировать из чата. Карточка показывает «Доступ выдан» без номера заявки.

Селектор также содержит другую команду и стажёра с неизвестным стендом. Это демонстрационный выбор учётной записи. Права определяются серверным профилем. Корпоративный вход и реальные сервисы Авито потребуют отдельных интеграций. Все инструкции и ссылки на задачи синтетические.

## Подключение модели

Без API-ключа сервер использует объяснение по выбранной инструкции. Пометка об этом видна в интерфейсе. Отправка и проверка заявки работают с базой данных.

В `.env` подготовлены настройки подключения.

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-6-luna
LLM_API_KEY=
LLM_ENABLED=true
LLM_TIMEOUT_SECONDS=15
```

Вставь ключ после `LLM_API_KEY=` и примени настройки.

```sh
docker compose up -d --force-recreate web
```

Клиент отправляет `POST {LLM_BASE_URL}/chat/completions`. Для AI Tunnel, DeepSeek, Kimi или другого совместимого провайдера укажи его API URL, точный ID доступной модели и ключ. Доступность конкретной модели зависит от провайдера и аккаунта. Название `gpt-6-luna` взято из [официального каталога OpenAI](https://developers.openai.com/api/docs/models). Контракт запроса соответствует [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

Для уже запущенного на хосте Ollama с OpenAI-совместимым API можно указать `http://host.docker.internal:11434/v1`, ID установленной модели и непустой фиктивный ключ. Модель должна быть установлена, а сервер доступен из контейнера. Конкретные провайдеры и платные запросы пока проверены через подмену HTTP-ответа в тестах. Живой вызов требует ключа.

Модель получает разрешённую инструкцию, вопрос, тестовую задачу и состояние доступа. Карточку и разрешённое действие формирует сервер. При таймауте или ошибке модели интерфейс показывает ответ по инструкции и сообщение о недоступности генерации. Ключ остаётся на сервере.

## Проверки

Для локальной разработки Flask можно запустить в виртуальном окружении с контейнерной базой.

```sh
docker compose up -d db
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/flask --app app run --port 5001
```

По умолчанию локальный Flask использует базу на `localhost:55432`. Если поменял `DB_PORT`, задай соответствующий `DATABASE_URL`.

Тесты используют отдельную базу с именем, заканчивающимся на `_test`. Создай её один раз.

```sh
docker compose exec db createdb -U buddy buddy_test
TEST_DATABASE_URL=postgresql://buddy:buddy-local-demo@localhost:55432/buddy_test \
  .venv/bin/python -m pytest --cov=app --cov=buddy --cov-report=term-missing
node --check static/app.js
```

Автотесты проверяют сохранение и повторную отправку, одновременное создание заявки, права, CSRF, неизвестный стенд, согласование, ошибку 403 после выдачи доступа, сбой до записи и потерю ответа после записи, резервные ответы модели. Покрытие относится к Python-коду. Отмена формы, отправка и перезагрузка дополнительно проверяются в браузере.

GitHub Actions на PR в `main` запускает тесты на PostgreSQL 17 с Python 3.13 и проверяет синтаксис JavaScript. Для запуска CI ключ модели не требуется.

Основные API — `GET /api/context`, `POST /api/chat`, `POST /api/requests`. Для POST требуются cookie сессии и заголовок `X-CSRF-Token` из HTML страницы. `POST /api/session` переключает заранее заданный тестовый профиль. Сервис заявок реализован в `buddy/service.py`, провайдер модели — в `buddy/llm.py`.
